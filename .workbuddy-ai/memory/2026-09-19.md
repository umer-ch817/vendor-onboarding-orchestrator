### Bugs fixed (all real, not environment noise)

1. `backend/requirements.txt` — missing `asyncpg`. `app/database/__init__.py` rewrites
   the URL to `postgresql+asyncpg://`, so the async engine could never start. Added
   `asyncpg==0.29.0`.
2. Same file — missing `pypdf`. `document_processing.py::_extract_pdf` imports
   `pypdf.PdfReader`; only PyPDF2 was installed, so every PDF raised
   `UnsupportedDocumentError`. Added `pypdf==4.0.1`.
3. `models/__init__.py` — GIN index on `vendors.legal_name` had no operator class.
   Postgres: "data type character varying has no default operator class for access
   method gin". Added `postgresql_ops={'legal_name': 'gin_trgm_ops'}` and
   `CREATE EXTENSION IF NOT EXISTS pg_trgm` in `backend/database/init.sql`
   (also applied by hand to the existing volume).
4. `models/__init__.py` — ambiguous relationships, mapper configure failures:
   - `User.approvals`: Approval has two FKs to users → added
     `foreign_keys="[Approval.requested_from_id]"`.
   - `User.audit_events`: `AuditEvent.actor_id` is NOT a FK (actors can be
     system/AI/n8n) → removed the collection side; `AuditEvent.user` is now
     `primaryjoin="AuditEvent.actor_id == User.id"` + `viewonly=True`.
   - `User.exceptions_resolved`: pinned to `Exception.assigned_to_id` explicitly.
5. `scripts/seed_demo_data.py` — imported non-existent `OnboardingType` (removed;
   it was unused). Also registered synthetic *text* content as `.pdf` /
   `application/pdf`, so every document failed to parse → changed to `.txt` /

## Third pass — n8n actually orchestrates now

The orchestration layer was inert: 4 workflows existed as JSON but were never
imported, and even once imported they could not call the backend.

10. Generated workflow JSON had no top-level `id` → n8n 2.39 rejected imports with
    `NOT NULL constraint failed: workflow_entity.id`. `build_workflows.py` now emits
    a STABLE id (uuid5 of the name) so re-import updates instead of duplicating.
    (Node ids stay random uuid4 — that asymmetry is deliberate and documented.)
11. `tags` were bare name strings → `NOT NULL constraint failed: workflows_tags.tagId`.
    Now emitted as `[{"id": uuid5(...), "name": ...}]`.
12. **The big one:** expressions in the generated JSON were missing the leading `=`.
    n8n only evaluates a parameter as an expression when it starts with `=`, so
    `{{ $env.VOR_BACKEND_URL }}` was stored as literal text →
    `Invalid URL: {{ $env.VOR_BACKEND_URL }}/api/webhooks/n8n`, and IF nodes compared
    the literal `{{ $json.submission_ok }}` against "yes" and always took the failure
    branch. Added `_expr()` helper in build_workflows.py and applied it to the three
    `$env` constants, `if_node`/`switch_node` leftValue, and `audit_node`
    event_type_expr.
13. `N8N_BLOCK_ENV_ACCESS_IN_NODE=false` was never set in docker-compose.yml even
    though build_workflows.py's comments said it was. Without it `$env.*` is blocked.
14. n8n 2.x removed `N8N_BASIC_AUTH_*` — documented `admin/admin123` is dead. The
    first UI visit creates the owner account. Removed the dead env vars + N8N_PASSWORD.

### Import/activate recipe (n8n 2.x)
`docker compose exec -T n8n n8n import:workflow --input=...` then
`n8n publish:workflow --id=<stable id>` then `docker compose restart n8n`
(publish does not take effect while n8n is running). Confirm with
`docker compose logs n8n | grep -i activated`.

### Proven round trip
POST http://localhost:5678/webhook/vendor-onboarding/case {"case_id":N,...,"action":"submit"}
→ audit trail gets WORKFLOW_TRIGGERED (N8N) → ASSESSMENT_COMPLETED (SYSTEM) →
AI_RISK_ANALYSIS (AI) → CASE_ROUTED (SYSTEM). Backend never calls n8n;
`N8N_WEBHOOK_URL` is declared but unread, and pipeline.py has no outbound call —
an earlier RUNBOOK claimed it did. Docs corrected.

### n8n activation is stateful and fragile — documented recipe
`n8n publish:workflow` warns "Changes will not take effect if n8n is running" and
only partially persists when exec'd against a live container. What reliably gets all
4 active: import → exec publish for each → `docker compose restart n8n`, then VERIFY
with `docker compose logs n8n | grep -c "Activated workflow"` (expect 4) and
`webhook_entity` rows for the two webhook workflows. A `docker compose up -d` that
recreates the container can silently drop activation back to 1 of 4.
Note `workflow_published_version` stays empty even when everything works — the
authoritative flag is `workflow_entity.active`.

### Debugging trick worth keeping
n8n stores executions in sqlite at /home/node/.n8n/database.sqlite. `docker cp` it
**plus the -wal and -shm files** (otherwise you read a stale DB and see zero
executions), then the execution_data blob is a flattened array with integer/string
references — resolve recursively to get per-node outputs and errors.
